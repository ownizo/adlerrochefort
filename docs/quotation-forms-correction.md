# Quotation forms correction — 18 September 2026

Implemented locally. No commit, push or deployment was performed. The pre-existing untracked `docs/private-client-audit-2026.md` was not edited.

## Existing architecture and the original commit

The repository already used Netlify Forms → `submission-created.mjs` → Resend internal notification, a privacy-restricted CRM lead, and Supabase `quote_requests`. The quote table stores `dados_comuns`, `dados_risco`, `pessoas_seguras`, `consentimento`, language, form identity, submission ID and test metadata. This pipeline is retained.

The existing browser system consists of `ar-quote-form.js`, `quote-wizard.js`, `quote-validators.js`, `quote-nationality.js`, `quote-field-toggle.js`, `lead-branch-fields.js` and `quote-health-persons.js`. It already provided three steps, localStorage drafts, honeypots, Portuguese validators, ISO nationality codes and dynamic Health blocks. No replacement frontend or submission pipeline was introduced.

Form ownership was mixed before this task. PL/SV/DA/ZH/HE wizards are generated by `scripts/lib/market-cluster.mjs` and product content modules. Older PT/EN/DE/NL wizards are explicitly hand-authored in public HTML; the repository's own `check-generator-freshness.mjs` documents this and the older car generator already refuses to overwrite them. Several older DE/NL/property generators still emitted obsolete forms. They now have the same overwrite guard. Their output must not be used to replace the authored wizards.

The shared form-only maintenance source is `scripts/lib/quotation-forms.mjs`, applied through `scripts/correct-quotation-forms.mjs` and the relevant existing generators. It changes form markup/copy and quotation links without regenerating surrounding page content. Its `--check` mode catches stale output. This follows the repository's existing post-processing architecture. Run it after legacy content generators; do not edit its generated corrections independently.

The commit comparison found **193 affected EN/DE pages containing forms**, with field-contract changes on only **five**. The dedicated Auto/Home/Health/Professional forms survived. The German Private Client wizard lost identification/address/NIF/date/start-date/GDPR fields when it became a household review; EN and Spain review forms changed their context/representative fields. The original commit added review registrations and representative CRM metadata; it did not replace the quote database or core validators. [Every affected page and field delta is recorded here](quotation-form-commit-audit.md).

## What was corrected

- Portugal Private Client pages, including Tavira, retain their household-review forms and content but now expose direct product quotation routes.
- Risk-specific quotation CTAs on affected short-form pages lead to existing full quotation flows. The old questions remain available in explicitly labelled enquiry forms. Condominium/TVDE and other specialist flows are not flattened into generic household forms.
- All ten homepage trees retain five visible fields: required name/email/insurance type, optional phone/company. Hidden attribution and honeypots remain. Risk branches and message fields no longer expand the homepage form. Old inline validators now respect optional fields.
- All core policyholder DOB fields enforce age 18. Insured-person dates only reject future/invalid dates.
- AL labels now mean full-time/part-time, retaining existing stored option codes `tempo_inteiro`/`parcial` for compatibility.
- Renovation checkbox state now has a name, survives drafts, and enables only its required year/description fields. Deselection clears and excludes them.
- Health has an explicit person count as well as the existing add/remove controls. The existing maximum of ten is retained. Drafts preserve the full insured-person array, including children; removing people removes their payload entries.
- French previously had only a short homepage form, and Dutch Auto had no dedicated wizard. Four French utility quote pages and one Dutch Auto page now reuse the existing market wizard. They are `noindex,follow` utility pages linked from the relevant homepage/product selector; no unrelated sitemap or SEO content was regenerated.
- Browser translation objects are generated from the ten existing JSON tables. French core translations and its 249-country list are complete. Core/common/country translation-key gaps now fail parity checks; older Life/Business/Private Client translation debt remains a warning outside this four-product scope.
- Form copy is protected from blanket EN/DE terminology normalization. EN form trust copy can retain “insurance broker”. No global terminology replacement was performed.

## Fields and validation

All four core flows require policyholder full name, Portuguese NIF, adult DOB, full address, locality, Portuguese postcode, phone, email, searchable nationality, fiscal-residence response, intended start date and GDPR consent. Address stays required for non-residents. Existing residence warnings remain, with shared support on the new pages.

| Product | Risk information |
|---|---|
| Auto | Portuguese plate and driving-licence date, plus common identification/address/start date. Four plate formats normalize to uppercase hyphenated values. |
| Home | Address/postcode, exclusive occupancy, conditional AL regime, construction year, gross area, bathrooms, optional renovations with required year and meaningful description when selected, building and contents sums. |
| Health | Explicit count and one block per insured person with full name, DOB and NIF. Children accepted. No clinical data. Existing forms required each insured NIF; no existing missing-NIF override was removed. |
| Professional/RC | Common identification/address/DOB/start date plus annual turnover. Existing specialist questionnaires and additional risk fields preserved. |

NIF checksum, postal masking, plate formats, licence/DOB consistency, non-past start date and renovation/construction-year checks are reused across languages. Impossible calendar dates now fail instead of silently rolling into another month. Numeric minimum/maximum/step constraints are now respected by the custom validator, with translated errors. Dates remain native ISO values; numeric inputs submit unformatted numeric values. No formatted currency/date strings are introduced into storage.

PT-only “Antes de preencher” blocks and cream/red styling remain where they existed, outside the fields. They were not copied into other languages. Hebrew layout and LTR numeric fields are preserved. Form controls/progress labels now fit narrow layouts and long translations; new utility pages avoid nested landing-page padding.

## Supabase, CRM and consent

No table, migration, schema, RLS policy, database service or CRM architecture was added or replaced. Read-only live inspection confirmed the expected columns and enabled RLS, with `quote_requests_select` restricted to authenticated users satisfying `is_admin()`. That function checks the authenticated user's admin role in `profiles`. Anonymous SELECT returned **zero rows**.

A synthetic Health row containing a child, French language metadata and consent was inserted into the actual table inside a transaction, checked, and rolled back. A follow-up query confirmed no test row remained.

The existing consent mapper now also recognises Private Client `privacy=accepted` and established consent aliases. Acceptance, server timestamp and privacy-policy version remain logged. **Existing limitation:** consent IP remains null because the Netlify submission event does not provide a reliably established end-user IP in this implementation. The function's own request IP would be the wrong substitute. No new endpoint was introduced merely to change this.

The CRM retains its existing restricted contact/attribution payload. Underwriting data continues to go into `quote_requests` and the internal notification, rather than being copied wholesale into CRM metadata. New FR/Dutch form identities are registered in the existing classification/notification maps. The German `telefon` contact alias is recognised. Health count, renovation state and explicit language metadata are preserved in the existing payload structure.

## Resend

Inspection found one existing internal-notification flow and **no customer acknowledgement send** in the repository handler. A translated customer acknowledgement has therefore been added to that same handler and Resend account. It uses the form language, has an idempotency key when a Netlify submission ID is available, and does not echo sensitive underwriting details to the customer. Existing test mode records the acknowledgement payload without sending it. Internal notifications still include all submitted fields and insured people; language is identified explicitly. Resend API error results are logged as well as thrown errors; email failures remain isolated from storage and CRM.

No real emails were sent during verification. Handler integration tests intercept both Resend calls and the Supabase insert and verify recipients, French acknowledgement content, complete insured-person data, consent and language. Actual delivery after deployment is not claimed: deployment was explicitly prohibited.

## Verification and limits

Results are recorded below after the final checks. Existing page-content overflow can still be present outside the forms (for example a pre-existing Swedish comparison table); unrelated content/layout was not redesigned. The four detailed quotation flows now collect the specified underwriting dataset at first submission, supporting quoting with minimal follow-up. Specialist underwriting/insurer acceptance can still require case-specific clarification; the forms no longer deliberately substitute a contact-only review for these product quotation flows.

All unrelated Private Client architecture, country navigation, technical content, hyperlocal content, representative positioning and SEO copy is preserved. Automated checks compare Portuguese content outside form regions against HEAD. No duplicate Supabase or Resend architecture was introduced.
